# Симулятор гиростабилизатора ESP32 + ICM-20948 (DMP) + MG90S

Интерактивный инструмент для исследования замкнутой системы «платформа с IMU - серва - регулятор» без железа:
меняйте коэффициенты, начальную ошибку, возмущения и параметры сервы, смотрите графики и показатели, сравнивайте
несколько KP и учитесь понимать, **почему** возникают колебания, перерегулирование или медленный возврат к нулю.

> **Главная оговорка.** Результаты зависят от точности модели. Динамика MG90S производителем не публикуется, поэтому
> параметры, помеченные в интерфейсе знаком ⚠, - допущения, а не измерения. Модель не идентична вашей реальной сервe, пока вы не
> подгоните её по своим измерениям (вкладка «Идентификация MG90S»). Сверяйте расчёт с экспериментом.

## Запуск на Windows

Нужен Python 3.10 или новее ([python.org](https://www.python.org/downloads/), при установке отметьте «Add Python to PATH»).

**Вариант 1 - двойной щелчок:** `run_simulator.bat` (создаёт `.venv`, ставит зависимости, запускает приложение; браузер откроется
на `http://localhost:8501`).

**Вариант 2 - вручную (cmd или PowerShell):**

```bat
cd путь\к\gimbal_simulator
py -3 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Интернет нужен только на этапе установки пакетов. Никаких ключей API и внешних сервисов нет; телеметрия Streamlit отключена
в `.streamlit/config.toml`.

## Проверки

```bat
python -m unittest discover -s tests -v        :: 38 автоматических проверок модели и регулятора
python tests\scenario_report.py                :: сводка типовых сценариев

```

Эти же проверки можно запустить кнопкой во вкладке «Проверки».

## Как пользоваться

Слева - параметры по группам (подсказка у каждого поля: смысл, единицы, статус достоверности и **как измерить**).
Сверху - четыре кнопки: **Запустить симуляцию**, **Перезапустить с текущими параметрами**, **Сбросить настройки**,
**Сравнить коэффициенты**. Изменение параметров не пересчитывает график само: после правок появляется отметка «график
показывает ПРЕДЫДУЩИЙ результат», пока вы не запустите новый расчёт.

- **Начальная ошибка** - начальное положение платформы (состояние, а не возмущение): платформа стартует отклонённой, регулятор всегда
  возвращает измеренный угол к 0°. Цель выбрать нельзя.
- **Внешние воздействия** (отдельно от начальной ошибки): ступень, импульс, синус, случайное возмущение основания.
- **Вкладки:** Симуляция; Сравнение KP (одинаковые условия для каждого KP); Сервопривод (испытания отдельно от контура);
  Идентификация MG90S (сравнение с вашими измерениями и подбор параметров); Проверки; Модель и данные; Экспорт (CSV, PNG, HTML).
- **JSON:** «Сохранить / загрузить набор параметров» в боковой панели.

## Модель

Одна ось, углы в градусах.

```
theta_p = theta_b + k_mech * theta_load          угол платформы = угол основания + k_mech * угол вала (после люфта нагрузки)
theta_IMU = theta_p                              IMU закреплена на платформе: движение вала меняет измерение
```

Порядок расчёта на каждом подшаге (не больше 1 мс): IMU видит ориентацию (пакеты DMP с частотой f_dmp, задержка, шум, фильтр) ->
регулятор по своему периоду считает целевой импульс по ПОСЛЕДНЕМУ пакету -> программный ограничитель скорости команды
(10 мкс за 20 мс, как в скетче; отключаемый) -> модель сервы получает ФАКТИЧЕСКИЙ импульс -> фактический угол вала ->
новая ориентация платформы. Целевой угол сервы нигде не подставляется вместо фактического.

**Регуляторы** (единицы: KP - мкс/град, KD - мкс/(град/с), Kθ - 1/с, Kω - мкс/(град/с)):

```
P        : c = -KP * угол
PD       : c = -(KP * угол + KD * скорость)
Каскад   : w_ref = clip(-Kθ * угол, ±w_max)
           скоростная форма : dc/dt = Kω * (w_ref - скорость)     (интегрирует ошибку скорости в команду)
           пропорциональная : c = Kω * (w_ref - скорость)         (математически = PD)
target = центр + s_cmd * c,   затем ограничение [pmin, pmax] и |c| <= MAX_CORRECTION
```

Статическое усиление петли `K = KP * (град вала на мкс) * k_mech * s_cmd * s_meas`. При `K > 0` обратная связь отрицательная,
остаток наклона основания равен `1/(1+K)`. Если команда обновляется очень редко (период много больше времени установления
сервы), для устойчивости нужно `K < 1`: при `K = 1` получается незатухающее чередование знака, при `K > 1` - рост до насыщения.

**Серва** (электромеханическая модель; можно выбрать упрощённую или идеальную для сравнения):

```
e = theta_ref - theta_out            потенциометр измеряет ВЫХОДНОЙ вал
u = clip(e / e_sat, -1, 1)           (0 внутри мёртвой зоны)
T = T_stall * (u - omega / omega_nl)
J * d(omega)/dt = T - c_v*omega - T_coulomb*sgn(omega) - T_grav - T_ext - J_load*k_mech*(ускорение основания)
```

Дополнительно: кадр PWM (серва читает импульс раз в кадр), задержка (дробная), мёртвая зона, люфт внутри контура (потенциометр на
выходном валу) и отдельно люфт нагрузки (мимо потенциометра), механические упоры, отключение сервы. Шум - отдельные параметры,
по умолчанию выключены.

**Упрощения.** Одномерная модель угла Twist (из кватерниона: `twist = 2*atan2(n.v, w)` для `q_rel = conj(q_ref)*q_now`; в
симуляторе этот шаг не воспроизводится - ось вала считается выбранной верно, swing = 0). Платформа жёсткая, расход тока и просадка
питания не моделируются.

## Что известно о MG90S, а что нет

| Характеристика | Значение | Достоверность |
|---|---|---|
| Время поворота на 60° без нагрузки | 0.10 с при 4.8 В; 0.08 с при 6 В | листинги продавцов совпадают между собой, независимо не проверено; зависит от напряжения и нагрузки |
| Стартовый момент | 1.8 кг·см (4.8 В); 2.2 кг·см (6 В) | листинги; зависит от напряжения |
| Ход вала | около 180° | листинги; реальный диапазон зависит от экземпляра и механических упоров |
| Мёртвая зона | 1-5 мкс | листинги расходятся |
| Аналоговая/цифровая | - | листинги противоречат друг другу; проверить на экземпляре |
| Структура | DC-мотор, редуктор, потенциометр на выходном валу, усилитель с насыщением | подтверждено описанием разборки родственной SG90 |
| Электромеханическая постоянная, коэффициент внутреннего контура, задержка, люфт, трение, инерция | **нет данных** | производитель не публикует; **определять измерением** |

По умолчанию `omega_nl` подгоняется так, чтобы модель повторяла паспортное время 60° (проверено для 4.8 и 6 В); `tau_a` и `e_sat`
- допущения, выбранные так, чтобы получилось слабо колебательное внутреннее звено (ζ около 0.8). Люфт, трение, нагрузка и
дополнительная задержка по умолчанию равны нулю (эффекты выключены), потому что надёжных данных нет.

### Как определить параметры вашей сервы

1. Закрепите корпус, на вал - платформу с IMU (или любой датчик угла). Питание - то, при котором работаете.
2. Подайте ступеньку команды (например, 1500 -> 2167 мкс, около 60°, и малую 1500 -> 1580 мкс, около 7°). Запишите время и угол с
   частотой не ниже 200 Гц.
3. Сохраните CSV (два столбца: время в секундах; угол в градусах; разделитель `;` или `,`, десятичная запятая допустима).
4. Вкладка «Идентификация MG90S»: добавьте измерения -> «Подобрать параметры» -> «Применить». Для надёжного подбора нужны и
   большая, и малая ступеньки. Подбор проверен только на синтетических данных, сгенерированных этой же моделью.
5. Люфт, задержку, мёртвую зону и инерцию измеряйте по подсказкам у соответствующих полей.

Проверено (запускалось): 38 автоматических проверок модели и регулятора; воспроизведение паспортного времени 60° для 4.8 и 6 В;
типовые сценарии (нулевая ошибка, малое и большое отклонение, насыщение, смена знака обратной связи, сравнение KP, медленное
обновление команды); подбор параметров на синтетических «измерениях»; сухой прогон кода интерфейса на **стендах-заменителях**
Streamlit и Plotly (сигнатуры старого и нового API).

**Не проверено:** запуск в настоящем Streamlit с настоящим Plotly (в среде разработки они не были установлены), отрисовка и
стили в браузере; соответствие модели вашей реальной серве (нет измерений).

## Типичные вопросы

- **Почему при обновлении раз в 5 с получается чередование ±угла?** Это дискретная петля: при `K = 1` (KP = 11.11 мкс/град при
  калибровке 11.11 мкс/град) неустойчивость нейтральная, при `K > 1` растёт до насыщения, при `K < 1` затухает.
  Замедление обновления и ограничение скорости только удлиняют колебание.
- **Почему при включённом ограничителе PWM разные KP дают одинаковые первые секунды?** Ограничитель (500 мкс/с) определяет скорость
  отклика; отключите его, чтобы увидеть влияние KP.
- **Почему при KP = 18 и быстром обновлении нет раскачки?** Для документированных параметров её и не должно быть: реальная раскачка
  требует суммарного запаздывания (задержка DMP, электроники сервы), которое в модели по умолчанию нулевое. Задайте измеренные
  задержки в группах «IMU / DMP» и «Сервопривод: динамика».
